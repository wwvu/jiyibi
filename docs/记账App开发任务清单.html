v2.1 数据库细节加固（开工前最后修正，优先级高于一切）
  1. 预算表 categoryId 改 NOT NULL DEFAULT 0：用 0 表示总预算（真实分类 id 从 1 开始，0 不冲突）。旧设计 nullable + unique(month, categoryId) 在 SQLite 中对 NULL 不生效，多条总预算可共存——约束形同虚设。改 0 后约束对所有行生效。
  2. sourceId 真正落 DB 唯一约束：Records 表加 uniqueKeys => [{sourceId}]。sourceId 可空，手记为 null（SQLite NULL 不冲突，多条手记 OK）；导入非空被 DB 直接拦截。应用层 batchInsertIfNew 是性能优化，DB 约束是兜底，双保险。
  3. sourceId 生成规则扩展：从 sha1(date+amountCents+categoryId) 扩展为 sha1(source|date|type|amountCents|categoryId|noteNormalized|merchantNormalized)。加入 type/note/merchant 避免同日同金额同分类误判（午饭和零食都 15 元餐饮不再被判重复）。note/merchant 规范化 = trim+lowercase，空则空串。
  4. 金额字符串直转 cents，不经 double：MoneyUtils.yuanToCents(String) 拆整数/小数部分直转（12*100+34=1234），小数超两位截断。旧 yuanToCents(double) => (yuan*100).round() 经过浮点表示，极端值有精度漂移。数字键盘全程字符串累积，最后一次性转。

MoneyUtils 实现（重要）
class MoneyUtils {
  /// 分 → 元字符串，带千分位：123456 → "¥1,234.56"
  static String formatYuan(int cents) {
    final neg = cents < 0;
    final abs = cents.abs();
    final yuan = abs ~/ 100;
    final frac = abs % 100;
    final yuanStr = yuan.toString().replaceAllMapped(
      RegExp(r'(\d)(?=(\d{3})+(?!\d))'),
      (m) => '${m[1]},');
    return '${neg ? '-' : ''}¥$yuanStr.${frac.toString().padLeft(2, '0')}';
  }

  /// 元字符串 → 分：不经 double，字符串直转。
  /// "12.34"→1234 / "12.3"→1230 / "12"→1200 / ""→0 / "-12.34"→-1234
  /// 小数超两位截断（不四舍五入，避免歧义）；非法格式返回 0
  static int yuanToCents(String yuan) {
    final s = yuan.trim();
    if (s.isEmpty) return 0;
    var neg = false;
    var body = s;
    if (body.startsWith('-')) { neg = true; body = body.substring(1); }
    else if (body.startsWith('+')) { body = body.substring(1); }
    final dot = body.indexOf('.');
    int yuanInt, fracInt;
    if (dot < 0) {
      yuanInt = int.tryParse(body) ?? 0;
      fracInt = 0;
    } else {
      yuanInt = int.tryParse(body.substring(0, dot)) ?? 0;
      var frac = body.substring(dot + 1);
      if (frac.length > 2) frac = frac.substring(0, 2);   // 截断到两位
      frac = frac.padRight(2, '0');                       // "3" → "30"
      fracInt = int.tryParse(frac) ?? 0;
    }
    final cents = yuanInt * 100 + fracInt;
    return neg ? -cents : cents;
  }

  /// 减法（分），避免溢出
  static int sub(int a, int b) => a - b;
}

class Records extends Table {
  IntColumn get id => integer().autoIncrement()();
  DateTimeColumn get date => dateTime()();
  TextColumn get type => text().withDefault(const Constant('expense'))(); // 'expense'|'income'
  IntColumn get amountCents => integer()();              // 金额，分，始终正数
  IntColumn get categoryId => integer().nullable()();
  TextColumn get note => text().nullable()();
  IntColumn get accountId => integer().withDefault(const Constant(1))();
  TextColumn get source => text().withDefault(const Constant('manual'))(); // manual|import|csv
  TextColumn get sourceId => text().nullable()();        // 导入去重键，DB 唯一约束（见下）
  TextColumn get merchant => text().nullable()();        // 商户/对方
  DateTimeColumn get createdAt => dateTime().withDefault(currentDateAndTime)();
  DateTimeColumn get updatedAt => dateTime().withDefault(currentDateAndTime)();
  @override
  List<Set<Column>> get uniqueKeys => [{sourceId}];   // 导入去重：手记 sourceId=null 不冲突，导入非空被 DB 拦截
}

class Categories extends Table {
  IntColumn get id => integer().autoIncrement()();
  TextColumn get name => text()();
  TextColumn get icon => text()();
  TextColumn get color => text()();
  TextColumn get type => text()();                        // 'expense'|'income'
  IntColumn get sortOrder => integer().withDefault(const Constant(0))();
  BoolColumn get archived => boolean().withDefault(const Constant(false))();
  @override
  List<Set<Column>> get uniqueKeys => [{name, type}];     // 同类型分类名唯一
}

class Accounts extends Table {
  IntColumn get id => integer().autoIncrement()();
  TextColumn get name => text()();
  IntColumn get balanceCents => integer().withDefault(const Constant(0))();
  TextColumn get icon => text().nullable()();
  BoolColumn get archived => boolean().withDefault(const Constant(false))();
  @override
  List<Set<Column>> get uniqueKeys => [{name}];
}

class Budgets extends Table {
  IntColumn get id => integer().autoIncrement()();
  IntColumn get month => integer()();                    // 202607
  IntColumn get amountCents => integer()();              // 预算，分
  IntColumn get categoryId => integer().withDefault(const Constant(0))();  // 0=总预算；真实分类 id 从 1 开始，0 不冲突
  @override
  List<Set<Column>> get uniqueKeys => [{month, categoryId}]; // 同月同分类唯一，含总预算(categoryId=0)
}
实现要点
  • AppDatabase 加 AppDatabase.forTesting(QueryExecutor e) : super(e) 构造，T1.6 内存库测试用
  • 运行 dart run build_runner build 生成 .g.dart
  • 数据库初始化：插入 8 个默认支出分类 + 3 个默认收入分类 + 1 个默认账户「现金」
  • 预算写入用 upsert（同 month+categoryId 存在则更新），依赖唯一约束。总预算行写 categoryId=0，同样走 upsert
  • MVP 不加密（明文），后续切 SQLCipher 只改 Database 定义一处
  • sourceId 去重是 DB 层 + 应用层双保险：DB 唯一约束（uniqueKeys={sourceId}）拦截并发/遗漏；应用层 batchInsertIfNew 先查已有 sourceId 集合批量过滤，避免逐条触发异常。生成规则：sha1(source|date|type|amountCents|categoryId|noteNormalized|merchantNormalized)，note/merchant 取 trim+lowercase，空则空串。含 type/note/merchant 避免同日同金额同分类误判
  • 不再有 nullable categoryId 的 NULL 问题：总预算用 0，真实分类从 1 开始，unique(month, categoryId) 对所有行生效
为什么用 archived 软删除而不是物理删除
删除分类/账户会破坏历史记录的外键完整性。归档后选择器隐藏，但历史流水仍能正确关联显示分类名。这是记账类应用的标准做法。
✅ 验收标准

  • App 启动后数据库创建，默认分类/账户已写入
  • 插入重复 (name,type) 分类会抛唯一约束异常
  • 插入重复 (month,categoryId) 预算会抛唯一约束异常；总预算 categoryId=0 也受约束（同月插两条 categoryId=0 会报错）

算法（int 分）
class BudgetPredictor {
  /// 预测月末支出（分）。daysPassed>0 才算
  static int predictMonthEndCents(
      int monthSpentCents, int daysPassed, int daysInMonth) {
    if (daysPassed <= 0) return 0;
    final dailyAvg = monthSpentCents ~/ daysPassed;  // 整除
    return dailyAvg * daysInMonth;
  }

  static bool willOverspend(int projectedCents, int budgetCents) =>
      projectedCents > budgetCents;

  /// 建议日均（分）。剩余预算 / 剩余天数
  static int suggestedDailyCents(
      int budgetCents, int monthSpentCents,
      int daysPassed, int daysInMonth) {
    final remaining = budgetCents - monthSpentCents;
    final daysLeft = daysInMonth - daysPassed;
    if (daysLeft <= 0) return 0;
    return remaining ~/ daysLeft;
  }
}

约定说明
命名文件 snake_case，类 PascalCase，变量 camelCase
状态管理统一 Riverpod，不用 setState（简单叶子组件除外）
数据库所有操作走 Repository，UI 不直接碰 Database
金额int 分存储（amountCents/balanceCents），禁止 double 运算金额。显示用 MoneyUtils.formatYuan，录入用 yuanToCents
归档分类/账户软删除（archived），不物理删除
约束categories unique(name,type)，accounts unique(name)，budgets unique(month,categoryId)
日志禁止 print，全走 AppLogger；日志不含金额/备注/商户；release 关 debug 日志
主题色所有颜色走 ColorScheme/ThemeData，不写死
语义色支出=#D85A30，收入=#3B6D11，所有主题不变
提交每 Task 单独 commit：feat(T1.3)/test(T1.6)/fix(...)
