一、执行摘要

这份报告围绕"做一个类似鲨鱼记账、优先满足自己记账需求"的目标展开。结论先行：

  • 市场已成熟，头部产品（鲨鱼记账、钱迹、随手记）下载量均达 5 亿级，但"自用优先"意味着可摆脱商业化包袱，聚焦核心记账体验。
  • 鲨鱼记账的核心打法是"极简 + 功能减法"，上手快、基础体验好；但存在 5 个明确痛点：预算超支不提醒、分类不够智能、报表深度不足、数据隐私有争议、缺乏账单自动导入。
  • 建议定位：一款极简、隐私优先、离线可用的个人记账工具，核心是"3 秒记一笔"，让记账成为习惯而非负担。
  • 差异化方向：AI 智能分类（补鲨鱼短板）、预算实时提醒、本地优先的数据架构、账单一键导入。
  • 实施策略：MVP 只做 6 个核心功能先满足自己，用真实场景打磨后再迭代，避免过度设计。

二、市场与竞品分析

2.1 市场概况

记账类 App 市场已高度成熟。根据第三方数据平台，鲨鱼记账与随手记的安装量均达 5 亿次级别，钱迹则以"零广告、零社交"的极简定位在年轻用户中快速增长。市场驱动力主要来自三方面：

  • "钱花哪了"的焦虑：移动支付普及后，消费无感化加剧了收支失控感，记账成为"找回掌控感"的手段。
  • 经济压力下的节流意识：近年经济环境下，"开源节流"从口号变成刚需，用户对预算和支出分析的需求上升。
  • 多渠道收入管理：副业、灵活就业普及，单一人需要管理多个收入来源，超出了支付平台自带账单的能力。

2.4 鲨鱼记账 SWOT 分析

优势 Strengths

  • 极简设计，3 步完成记账，新手友好
  • 基础版无广告，体验干净
  • 坚持"功能减法"，不做加法，专注核心
  • 日历视图直观，预算/定时记账实用

劣势 Weaknesses

  • 预算设置了但超支时不提醒
  • 分类不够智能，需手动选择
  • 报表深度不足，缺自定义图表
  • 数据隐私有争议（曾涉广告推送）
  • 无账单自动导入，全靠手动

机会 Opportunities

  • AI 赋能：智能分类、消费预测
  • 账单导入：对接支付宝/微信减少手动输入
  • 隐私优先定位：本地加密 + 可选云同步
  • 经济下行期节流需求上升

威胁 Threats

  • 钱迹等竞品已在极简赛道站稳
  • 支付平台自带账单功能替代部分需求
  • 用户记账坚持率低，留存难
  • 银行/支付 App 直接做记账功能
关键洞察：鲨鱼记账的"功能减法"是双刃剑——它换来了极简体验，但也留下了预算提醒、智能分类、账单导入等明确缺口。这些缺口不是"锦上添花"，而是用户反复提及的痛点，正是新产品切入的机会。

三、用户需求分析

3.1 目标用户画像

由于产品"优先满足自己记账需求"，核心用户就是你自己，同时辐射到与你类似的用户群：

有记账意愿但难坚持

想记账，但每次打开 App 流程太长就放弃。核心诉求：记账要快，最好 3 秒内完成。

想知道钱花哪了

月底摸不清钱去哪了，需要清晰的分类统计和趋势图。核心诉求：看得清、看得懂。

想控制预算

定了预算但总超支，且超了才知道。核心诉求：实时预算反馈，快超时提醒。

在意数据安全

不想财务数据存在别人服务器上被分析/推送广告。核心诉求：数据自主可控。

四、产品定位建议

定位声明

一款极简、隐私优先的个人记账工具——3 秒记一笔，让记账成为习惯而非负担。

不追求大而全，不堆砌社交和理财功能。把"记账体验"做到极致：快、准、不烦。数据默认存在你自己的设备上，加密且可导出，你对自己的财务数据拥有完全主权。

4.1 核心价值主张

极速记账

数字键盘 + 常用分类快捷入口，目标 3 秒完成一笔。常用分类自动前置，减少选择成本。

清晰流向

收支日历 + 分类占比 + 趋势曲线，一眼看清钱花哪了、比上月多还是少。

智能预算

每笔记账实时显示剩余预算，接近上限主动提醒，超支醒目警告——这是鲨鱼记账缺的关键一环。

数据自主

本地加密存储为默认，云同步可选且端到端加密。数据随时可导出，不做数据绑架。

5.2 三阶段迭代规划

MVP · 先满足自己
  • 收支快速记账：数字键盘 + 分类选择 + 备注，3 秒目标
  • 分类管理：预设常用分类 + 自定义，常用自动前置
  • 月度预算 + 实时提醒：每笔显示剩余，临近预警
  • 收支日历视图：每日收支一目了然
  • 基础统计报表：月度收支汇总 + 分类占比饼图
  • 本地存储 + 导出：SQLite 加密存储，CSV/Excel 导出

目标：用自己的真实记账场景跑通闭环，打磨记账速度和预算提醒。

V1 · 体验完善
  • 图表深度分析：趋势折线、分类排行、同比环比
  • 定时/周期记账：固定开支（房租/订阅）自动记录
  • 账单导入解析：导入支付宝/微信账单 CSV，自动生成记录
  • 多账户管理：现金/银行卡/信用卡分账户记录
  • 端到端加密云同步：可选，跨设备同步
  • 搜索与标签：按金额/分类/备注/标签快速检索

目标：补齐期望型需求，减少手动操作，提升分析深度。

V2 · 差异化
  • AI 智能分类：根据备注/金额/商户自动匹配分类
  • 存款目标计划：设定目标、追踪进度、可视化激励
  • 信用卡账单管理：账单日/还款日提醒、账单分期
  • 报销单据管理：拍照记录、标记报销状态
  • 多账本/共享记账：家庭账本、旅行账本
  • 数据看板定制：自定义首页卡片和报表

目标：做鲨鱼记账没做的兴奋型需求，建立差异化壁垒。

六、差异化亮点建议

以下是针对鲨鱼记账痛点的 5 个差异化方向，按优先级排序：

优先级 1 预算实时提醒系统

鲨鱼记账最大的槽点就是"预算设了但超了才知道"。建议：每笔记账后实时更新并显示剩余预算；达到 80% 弹出温和预警；达到 100% 醒目警告并显示超支金额；分类预算（餐饮/交通等）独立追踪。这是低成本高感知的改进。

优先级 2 AI 智能分类

用户输入金额和备注后，自动推荐分类。MVP 阶段用"规则匹配 + 用户习惯记忆"即可（如：备注含" Starbucks"→餐饮→咖啡）；V2 可引入轻量模型。常用分类自动前置，进一步减少选择。这一步能显著降低记账的"烦"。

优先级 3 账单一键导入

用户从支付宝/微信导出账单 CSV，App 解析后批量生成记账记录，用户只需确认/微调分类。这解决了"支付平台已有账单还要手动搬"的痛点，大幅降低记账负担。注意做好去重和分类映射。

优先级 4 本地优先数据架构

数据默认本地 SQLite 加密存储，不上云。云同步作为可选项，且采用端到端加密（用户持密钥）。明确宣传"你的财务数据只属于你"，建立隐私信任。这直接回应用户对鲨鱼记账的隐私顾虑。

优先级 5 极速记账交互

核心记账页：大号数字键盘 + 金额实时显示 + 横向滑动的常用分类条 + 快速备注。打开 App 直接进入记账页（可配置）。支持快捷方式/小组件一键进入记账。目标是让"记一笔"的摩擦力降到最低。

七、技术选型建议

层级推荐方案理由
移动端框架Flutter一套代码覆盖 iOS/Android，UI 性能接近原生，适合个人开发者维护；社区成熟，记账类 UI 组件丰富
备选React Native若熟悉前端技术栈；生态更广但性能略逊 Flutter
本地存储SQLite + SQLCipher 加密轻量、可靠、加密保护隐私；结构化查询方便报表统计
状态管理Flutter: Riverpod / Bloc记账 App 状态较简单，无需过度工程化
图表库fl_chart（Flutter）开源、轻量、可定制，支持饼图/折线/柱状
云同步可选：自建后端（Node.js/Go）+ 端到端加密V1 阶段再做；加密在客户端完成，服务器只存密文
AI 分类本地规则引擎 + 用户习惯学习（V2 可选云端模型）MVP 不依赖网络，离线可用；先规则后模型，渐进增强
账单解析CSV 解析 + 分类映射规则支付宝/微信账单格式固定，正则解析即可
开发建议：作为"优先满足自己"的项目，建议从 Flutter + SQLite 起步，先做 Android 单平台验证 MVP（用自己的安卓机日常使用），跑顺后再补 iOS。不要一开始就上云同步和后端，那是 V1 的事。

八、总结与行动建议

行动路线

  1. 第一步（1-2 周）：用 Flutter 搭建 MVP，实现快速记账 + 分类 + 预算提醒 + 日历 + 基础报表 + 本地存储。这个阶段只服务你自己。
  2. 第二步（2-4 周）：日常使用 MVP，记录所有"不顺手"的地方，迭代打磨记账速度和预算提醒体验。目标：记账变成肌肉记忆。
  3. 第三步：补齐图表分析、定时记账、账单导入，进入 V1。
  4. 第四步：根据使用数据决定差异化方向，AI 分类 / 存款计划 / 云同步按需推进。
一句话总结：别学鲨鱼记账做加法，也别学它把"预算提醒"这种关键功能砍掉。做一个"记账快、预算狠、数据归你"的工具，先把自己伺候好，产品就有了根。
